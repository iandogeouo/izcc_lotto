# 大樂透模擬網站 — 開發需求 Prompt

## 專案目標
請幫我建立一個「大樂透模擬」網站，包含**玩家頁面（唯讀公開頁面）**與**管理後台（由我操作下注）**兩大部分。整個系統應該是可以本機執行的全端專案（前端 + 後端 + 資料庫），資料要能持久化保存（例如用 SQLite 或其他輕量資料庫即可），不需要真的串接金流。

**重要架構說明：**
- 玩家不會自己上網下注，玩家只能「看」，是唯讀頁面，不需要登入。
- 所有下注紀錄都是由我（管理者）在後台輸入操作，模擬玩家下注的情境。
- 後台**不需要密碼保護或登入機制**，這是純本機自用的模擬專案，直接開放存取即可。

---

## 技術棧建議（可依你的判斷調整，但請說明理由）
- 前端：React（或 Next.js）
- 後端：Node.js（Express 或 Next.js API routes 皆可）
- 資料庫：SQLite（開發簡單、單檔案、易於檢視資料）
- 請用 TypeScript

## 功能一：玩家頁面（公開唯讀頁，不需登入）
給玩家/一般人看的畫面，只能查看，**不能在這裡下注**：

1. **本期開獎號碼**
   - 顯示 6 個一般號碼 + 1 個特別號
   - 若尚未開獎，顯示「尚未開獎」與下次開獎時間
2. **目前累積總獎池金額**
   - 若本期頭獎從缺，獎池金額要能累積到下一期
3. **中獎方式說明表**，至少包含以下對獎規則（可參考台灣大樂透規則，但獎金計算方式簡化如下，實際比例你可以幫我抓合理預設值）：

   | 獎項 | 對中方式 | 獎金規則 |
   |---|---|---|
   | 頭獎 | 中6個號碼 | 由所有頭獎得主均分「總獎池」（唯一會累積的獎項），給一個底金可能5,000,000之類的，然後所有人的投注金額加上去|
   | 貳獎 | 中5個號碼+特別號 | 固定金額（每注固定，例如 3,000,000 元） |
   | 參獎 | 中5個號碼 | 固定金額（例如 200,000 元） |
   | 肆獎 | 中4個號碼 | 固定金額（例如 20,000 元） |
   | 伍獎 | 中3個號碼 | 固定金額（例如 2,000 元） |
   | 陸獎 | 中2個號碼+特別號 | 固定金額（例如 400 元） |
   | 普獎 | 未中任何號碼但中特別號 | 固定金額（例如 400 元） |

   除了頭獎以外，其餘各獎項金額都是固定的，不會因為中獎人數而改變，也不會累積到下一期；只有頭獎是「均分獎池」且會在從缺時累積。請把頭獎～普獎這些固定金額寫成可設定的參數（例如 config 檔或資料庫設定表），方便之後調整。
   每一注的金額也請幫我改成可以設定的

4. **目前下注統計**（讓玩家能看到現在大家下注的狀況）：
   - 本期「總下注注數」
   - 每個號碼（1–49）目前被下注的次數統計（例如長條圖或表格，方便看出熱門/冷門號碼）
5. **查詢我的下注**：
   - 提供一個下拉選單，讓玩家從固定的「玩家名單」中選擇自己的名字（名單見下方「固定玩家名單」章節），選完後查出這個人本期下了哪幾注（每注的 6 個號碼）
   - 若已經開獎，同時顯示每一注的對獎結果（中幾個號碼、是否中特別號、對應獎項、獎金）
   - 不需要密碼或登入，選單選擇即可查詢
6. **歷史開獎紀錄列表**（可選，若時間允許）：過去幾期的開獎號碼與獎池金額

## 功能二：管理後台（我操作，不需登入/密碼保護）
這是我用來模擬「玩家下注」的操作介面，只有我自己在本機使用，不用做任何權限控管：

1. **下注輸入功能**
   - 玩家不是自由輸入文字，而是從固定的「玩家名單」（共 36 位，見下方「固定玩家名單」章節）用**下拉選單**選擇這筆下注是哪位玩家買的
   - 從 1–49 選 6 個號碼建立一筆下注（可以做「手動選號」與「隨機選號」兩種方式，方便我快速產生大量模擬下注）
   - 一次可以輸入多注，選單選好玩家後可以連續幫同一位玩家新增多注，不用每注都重選一次
   - 每注都要記錄：玩家（對應到 Player 表的 ID）、選擇的 6 個號碼、下注時間、屬於哪一期

2. **下注紀錄管理**
   - 可以看到目前這一期所有已輸入的下注紀錄列表
   - 需要能依「期別」查詢所有下注紀錄
   - 若有輸入錯誤，可以刪除/編輯單筆下注紀錄

3. **開獎與對獎功能**
   - 提供一個觸發開獎的按鈕，系統隨機產生 6 個號碼+1 個特別號
   - 開獎後自動對獎，計算每位玩家每注中了幾個號碼、屬於哪個獎項、應得獎金
   - 若頭獎從缺，頭獎獎金累積到下一期總獎池；貳獎～普獎是固定金額，不會累積、也不受從缺影響
   - 開獎後，玩家頁面應自動顯示最新結果

## 資料結構建議（請依此設計資料表，若有更好的設計也歡迎調整）

- **Draw（期別）**：期別編號、開獎時間、開獎狀態（未開獎/已開獎）、開出的 6 個號碼、特別號、本期頭獎獎池金額（貳獎～普獎金額是固定的，存在 config／設定表，不需要每期各存一份）
- **Bet（下注紀錄）**：下注 ID、期別 ID、玩家識別、選擇的 6 個號碼、下注時間、對獎結果（中幾個號碼、是否中特別號、對應獎項、獎金，開獎後才會填入）
- **Player（玩家）**：玩家 ID、姓名。這是固定名單（見下方「固定玩家名單」），**不需要開放新增/刪除玩家的功能**，seed 資料時直接把 36 位玩家匯入資料庫即可，前台下拉選單與後台下拉選單都是讀這張表。

## 其他要求
1. 請用簡單的 seed script 產生一些測試資料（先把上面 36 位玩家匯入 Player 表，再產生幾期歷史開獎 + 一些模擬下注紀錄），方便我一啟動就能看到畫面效果，不是空的。
2. 畫面風格不用太花俏，乾淨清楚、手機也能看即可（響應式）。
3. 請把「對獎邏輯」（判斷中幾個號碼、對應到哪個獎項）獨立寫成一個可以單獨測試的函式/模組，並附上幾個簡單的單元測試，確保邏輯正確（例如：中6個=頭獎、中5個+特別號=貳獎…等各種情況都要測到）。
4. 玩家頁面與管理後台可以是同一個網站底下的不同路由（例如 `/` 是玩家頁面、`/admin` 是管理後台），不需要分成兩個獨立專案。
5. 請先跟我確認整體資料夾結構與技術選型，再開始寫程式；如果有任何規則不確定（例如各獎項獎金比例怎麼分配），先用合理預設值並註明在說明文件中，不用特別停下來問我。
6. 完成後請提供啟動方式說明（如何安裝依賴、如何啟動前後端、如何跑測試）。
